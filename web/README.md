# BranchLab evidence dashboard

A real report-driven Next.js/React interface. There are no synthetic fallback reports or fabricated metrics. With no API or no investigations it displays an actionable connection/empty state.

## Run

From the repository root, start the evidence API:

```sh
branchlab serve --host 127.0.0.1 --port 8765
```

In this directory:

```sh
npm ci
npm run dev
```

Open **http://127.0.0.1:3000**. `Run local demo` executes the bundled trusted deterministic fixture through the backend. It really creates revisions and runs probes; the resulting plan is explicitly labeled **not live AI**. Reports generated by live providers, supplied plans, and replays retain their own provenance. New CLI runs appear on refresh.

`BRANCHLAB_API_URL` is server-only and defaults to `http://127.0.0.1:8765`. It must be an HTTP(S) origin without paths or embedded credentials. Unconfigured local mode accepts only loopback Host authorities. Authenticated remote deployment is supported through the exact origin and three server-only secrets described in [DEPLOYMENT.md](../docs/DEPLOYMENT.md). Missing or partial remote authentication configuration fails closed. To change local ports, invoke `next dev`/`next start` with the desired `--port`.

## Capabilities

- Actual run history, immutable revision identifiers and reported summary counts
- Classification/search filtering and finding selection
- Side-by-side base/head HTTP responses and assertions, including each recorded repeat
- Source citations and validation outcomes
- Static source relationship graph with accessible textual relationships
- Declarative probe definitions, minimization outcomes and copyable replay commands
- Markdown and JSON downloads
- GitHub PR submission, queued/running/completed job tracking, and links to completed evidence
- Private remote workspace with owner login, eight-hour signed sessions, and logout
- Keyboard focus states, skip link, mobile layout, reduced motion support and loading/errors

The server-side proxy permits only evidence reads/downloads, bounded integer job reads, same-origin JSON `POST /api/demo`, and `POST /api/investigations` with exactly one GitHub pull-request URL. The App backend independently requires an installed, explicitly allowed repository. No client-controlled paths, runner selection, model setting, test code, or command execution are accepted. It validates Host, Origin, request size, run/job IDs, and upstream configuration; rejects redirects; caps responses; and forwards only its configured server-side bearer token, never browser cookies or client authorization. Signed GitHub webhooks route separately to the API, not through the dashboard proxy.

## Verify

```sh
npm test
npm run typecheck
npm run build
npm run smoke:auth
```

For a real browser smoke test, start the backend and dashboard first, then:

```sh
CHROME_PATH=/usr/bin/google-chrome node scripts/smoke.mjs
```

The local smoke script uses a dedicated headless browser (not any existing user browser), executes one demo, verifies its successful response and new run, switches through evidence views, tests search, downloads the report, checks mobile overflow and browser errors, and verifies rejected cross-origin writes/malformed paths. It writes the desktop screenshot to `../docs/dashboard.png` and an ignored local mobile screenshot. A system Chrome executable or `CHROME_PATH` is needed; the script does not install a browser.

`npm run smoke:auth` launches the production standalone server, real evidence API, and an ephemeral loopback HTTPS reverse proxy. It exercises login, HttpOnly/Secure cookies, logout, rate limits, protected API/downloads, server bearer forwarding, an actual paired-execution demo, PR setup errors, and desktop/mobile layout. It needs the repository `.venv`, OpenSSL, Chrome, and a completed build. Credentials and certificates are ephemeral test data; it does not install a real GitHub App or deploy publicly.

## Production

```sh
npm run build
npm start
```

No API key belongs in the dashboard. Model setup is handled by the backend CLI.
