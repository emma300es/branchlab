# BranchLab evidence dashboard

A real report-driven Next.js/React interface. There are no synthetic fallback reports or fabricated metrics. With no API or no investigations it displays an actionable connection/empty state.

## Run

From the repository root, start the evidence API:

```sh
branchlab serve --host 127.0.0.1 --port 8765
```

In this directory:

```sh
npm ci
npm run dev
```

Open **http://127.0.0.1:3000**. `Run local demo` executes the bundled trusted deterministic fixture through the backend. It really creates revisions and runs probes; the resulting plan is explicitly labeled **not live AI**. Reports generated by live providers, supplied plans, and replays retain their own provenance. New CLI runs appear on refresh.

`BRANCHLAB_API_URL` is server-only and defaults to `http://127.0.0.1:8765`. It must be an HTTP(S) origin without paths or embedded credentials. The UI and its proxy are intentionally loopback-only; remote access/authentication requires a separately designed deployment rather than simply binding it publicly. To change local ports, invoke `next dev`/`next start` with the desired `--port`.

## Capabilities

- Actual run history, immutable revision identifiers and reported summary counts
- Classification/search filtering and finding selection
- Side-by-side base/head HTTP responses and assertions, including each recorded repeat
- Source citations and validation outcomes
- Static source relationship graph with accessible textual relationships
- Declarative probe definitions, minimization outcomes and copyable replay commands
- Markdown and JSON downloads
- Keyboard focus states, skip link, mobile layout, reduced motion support and loading/errors

The server-side proxy permits only `GET /api/runs`, `GET /api/runs/{id}`, the report Markdown/JSON downloads, and same-origin JSON `POST /api/demo`. It validates the Host authority, exact run-ID format and upstream configuration, rejects redirects, caps responses, and does not forward cookies or authorization. It cannot submit arbitrary repositories or execute arbitrary commands. The backend's separate `plan.json` artifact remains available via its local API/CLI, not via this minimal UI proxy.

## Verify

```sh
npm test
npm run typecheck
npm run build
```

For a real browser smoke test, start the backend and dashboard first, then:

```sh
CHROME_PATH=/usr/bin/google-chrome node scripts/smoke.mjs
```

The smoke script uses a dedicated headless browser (not any existing user browser), executes one demo, verifies its successful response and new run, switches through evidence views, tests search, downloads the report, checks mobile overflow and browser errors, and verifies rejected cross-origin writes/malformed paths. It writes the desktop screenshot to `../docs/dashboard.png` and an ignored local mobile screenshot. A system Chrome executable or `CHROME_PATH` is needed; the script does not install a browser.

## Production

```sh
npm run build
npm start
```

No API key belongs in the dashboard. Model setup is handled by the backend CLI.
